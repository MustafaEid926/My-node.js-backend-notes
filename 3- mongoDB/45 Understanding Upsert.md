
## **مقدمة: ما هو مفهوم (Upsert)؟**
بعد أن تعرّفنا في المحاضرات السابقة على معاملات الحقول مثل معامل الإلغاء (`unset$`) ومعامل إعادة التسمية (`rename$`)، ننتقل الآن إلى خيار قوي ومفيد جداً يمكن تمريره لدوال التحديث، وهو خيار الـ **Upsert**.

*   **التعريف البرمجي:** مصطلح **Upsert** هو دمج بين كلمتي **Update** (تحديث) و **Insert** (إدراج). 
*   **آلية العمل:** هو خيار يسمح لك بتنفيذ عملية مزدوجة؛ فإما أن يقوم بـ **تحديث مستند موجود (Update an existing document)** إذا كان يطابق شروط الاستعلام، أو يقوم بـ **إدراج مستند جديد (Insert a new document)** في حال لم يتم العثور على أي Document يطابق تلك الشروط.
*   **دوال التحديث:** يمكن تمرير هذا الخيار كمعامل ثالث (**Third Argument**) لدوال التحديث مثل **`updateOne`** أو **`updateMany`** .

---

## **أولاً: السلوك الافتراضي لعمليات التحديث (Default Behavior)**
لفهم أهمية الـ **Upsert**، يجب أولاً فهم كيف تتصرف قاعدة البيانات بدونه.
*   **القيمة الافتراضية:** بشكل افتراضي، تكون قيمة خيار `upsert` معينة على **`false`**.
*   **السلوك:** إذا قمت بمحاولة تحديث Document بناءً على معيار تصفية (**Filter Criteria**)، ولم تعثر **MongoDB** على أي Document يطابق هذا المعيار، فإنها ببساطة **لن تفعل شيئاً**. لن يتم تحديث أي شيء، ولن يتم إدراج أي بيانات جديدة .

### **التطبيق العملي 1: تحديث Document موجود (بدون Upsert)**
في مجموعة الموظفين **`employees`**، لدينا Document لموظف يُدعى "John do". نريد تحديث عمره (`age`) إلى `34`، وتحديث مصفوفة هواياته (`hobbies`) لتصبح "sports" و "running" .

```javascript
db.employees.updateOne(
    { name: "John do" }, // المعامل الأول: معيار التصفية
    { 
        $set: {          // المعامل الثاني: القيم المراد تحديثها أو إضافتها
            age: 34, 
            hobbies: ["sports", "running"] 
        } 
    }
)
```
*   **تحليل النتيجة:** بما أن الموظف "John do" موجود بالفعل في المجموعة، سيرجع الخادم النتيجة: `matchedCount: 1` (تم العثور على Document مطابق) و `modifiedCount: 1` (تم التعديل بنجاح). تمت إضافة حقل العمر لأنه لم يكن موجوداً، وتغيرت الهوايات.

### **التطبيق العملي 2: محاولة تحديث Document غير موجود (بدون Upsert)**
الآن، ماذا لو حاولنا تنفيذ نفس الكود السابق ولكن بالبحث عن موظف يُدعى "Steve Smith" (وهو غير موجود في قاعدة البيانات)؟

```javascript
db.employees.updateOne(
    { name: "Steve Smith" }, 
    { $set: { age: 34, hobbies: ["sports", "running"] } }
)
```
*   **تحليل النتيجة:** سيرجع الخادم: `matchedCount: 0` و `modifiedCount: 0`. لم يحدث أي تغيير في المجموعة (**Collection**)، لأنه لم يعثر على الDocument، وبما أن `upsert` افتراضياً هو `false`، فلم يتم إدراج أي Document جديد.

---

## **ثانياً: تفعيل خاصية (Upsert: true)**
لتغيير السلوك الافتراضي السابق، نقوم بتمرير كائن خيارات كـ **معامل ثالث (Third Argument)** لدالة التحديث، ونقوم بتعيين خاصية `upsert` إلى **`true`** .

### **التطبيق العملي 3: التحديث مع تفعيل Upsert لDocument غير موجود**
سنعيد تنفيذ الكود الخاص بالموظف "Steve Smith"، ولكن هذه المرة مع تفعيل خيار الـ **Upsert**.

```javascript
db.employees.updateOne(
    { name: "Steve Smith" }, // المعامل الأول: التصفية
    { $set: { age: 34, hobbies: ["sports", "running"] } }, // المعامل الثاني: التحديث
    { upsert: true } // المعامل الثالث: تفعيل خاصية الـ Upsert
)
```
*   **تحليل النتيجة المعمارية (Output Analysis):**
    * `‏`  `matchedCount: 0` : لم يتم العثور على Document يطابق الاسم "Steve Smith" .
    *  `‏`  `modifiedCount: 0` : لم يتم التعديل على أي Document موجود لأنه لا يمكن تعديل Document غير موجود.
    * `‏`   **`upsertedCount: 1`** : هنا يكمن الفارق! تم إدراج (**Inserted**) Document جديد واحد بنجاح في قاعدة البيانات.

---

## **ثالثاً: كيف يتم بناء الDocument الجديد عند الإدراج؟ (New Document Construction)**
هناك قاعدة معمارية هامة جداً تطبقها **MongoDB** عند إنشاء الDocument الجديد عبر خاصية **Upsert**:
*   الDocument الجديد لن يحتوي فقط على الحقول الموجودة داخل معامل التحديث **`set$`** (مثل `age` و `hobbies`).
*   بل سيقوم المحرك **بدمج** الحقول التي استخدمتها في معيار التصفية (**Filter Criteria**) مع الحقول الموجودة في التحديث لتكوين الDocument النهائي .

**هيكل الDocument الجديد "Steve Smith" في قاعدة البيانات سيكون كالتالي:**
1. `‏`  **`id_`**: يتم توليده تلقائياً (Object ID) كأي Document جديد.
2. `‏` **`name: "Steve Smith"`**: تم استخراج هذا الحقل وقيمته من معيار التصفية وإضافته للDocument.
3. `‏` **`age: 34`**: تم استخراجه من معامل التحديث `set$`.
4. `‏` **`hobbies: ["sports", "running"]`**: تم استخراجه من معامل التحديث `set$`.

## **الخلاصة (Conclusion)**
تُعد خاصية **Upsert** أداة قوية للغاية لمهندسي قواعد البيانات، فهي تقلل من كتابة الأكواد البرمجية (**Boilerplate Code**) في الواجهة الخلفية (**Backend**). فبدلاً من كتابة استعلام للبحث عن الDocument، ثم كتابة جملة شرطية (**If statement**) للتحقق من وجوده لتقرر ما إذا كنت ستستخدم دالة إدراج (`insert`) أو تحديث (`update`)، يتكفل خيار `{ upsert: true }` بالقيام بالمنطقين معاً في استعلام واحد وبكفاءة عالية .
