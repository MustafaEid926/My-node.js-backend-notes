
## **مقدمة: ما هي المعاملات المنطقية (Logical Operators)؟**
في عالم قواعد البيانات، غالباً ما نحتاج إلى استرجاع بيانات بناءً على أكثر من معيار واحد في نفس الوقت. 
*   **الوظيفة الأساسية:** تسمح لك المعاملات المنطقية في **MongoDB** بدمج شروط متعددة (**Combine multiple conditions**) داخل استعلام واحد (**Query**). 
*   **الهدف المعماري:** تُستخدم هذه المعاملات لإنشاء استعلامات أكثر تعقيداً ومرونة ودقة (**Complex and flexible queries**).
*   **الأنواع:** تدعم **MongoDB** أربعة معاملات منطقية رئيسية وهي: المعامل `or$`، المعامل `nor$`، المعامل `and$`، والمعامل `not$`.

---

## **أولاً: معامل التخيير (or Operator$)**

### **المفهوم وآلية العمل**
*   **التعريف:** يُستخدم المعامل `or$` لفلترة الDocumentات التي تستوفي **أي شرط واحد على الأقل** من قائمة الشروط المحددة.
*   **آلية المعالجة:** سيقوم محرك قاعدة البيانات باختبار الDocument؛ إذا كان يحقق الشرط الأول فسيتم إرجاعه، وإن لم يحققه سيختبر الشرط الثاني، وإذا حققه سيتم إرجاعه، وهكذا. الDocument الذي لا يحقق أياً من الشروط هو فقط من يتم استبعاده .

### **التطبيق العملي والصياغة البرمجية (Syntax)**
*   **المثال:** نريد البحث في مجموعة المنتجات `products` عن المنتجات التي تقييمها (`ratings`) أكبر من أو يساوي `9`، **أو** المنتجات التي تحتوي فئتها (`category`) على الكلمة `"mobile"` .
*   **القاعدة البرمجية:** يجب أن نُسند لمعامل `or$` مصفوفة (**Array**)، وبداخل هذه المصفوفة نمرر كائنات (**Objects**)، بحيث يمثل كل كائن شرطاً مستقلاً .

```javascript
db.products.find({
    $or: [
        { ratings: { $gte: 9 } }, // الشرط الأول
        { category: "mobile" }    // الشرط الثاني
    ]
})
```
*   **تحليل النتيجة:** سيعيد هذا الاستعلام قائمة بالمنتجات. قد تجد منتجاً تقييمه `8.2` (لم يحقق الشرط الأول)، ولكنه ظهر في النتائج لأن فئته تحتوي على `"mobile"` (حقق الشرط الثاني). والعكس صحيح.

---

## **ثانياً: معامل النفي المطلق (nor Operator$)**

### **المفهوم وآلية العمل**
*   **التعريف:** المعامل `nor$` هو العكس تماماً للمعامل `or$`. 
*   **الوظيفة:** يُستخدم لمطابقة واسترجاع الDocumentات التي **لا تطابق أيّاً (Do not match any)** من الشروط المحددة .
*   **آلية المعالجة:** لكي ينجح الDocument ويظهر في النتائج، يجب أن يفشل في جميع الشروط المكتوبة.

### **التطبيق العملي**
*   **المثال:** باستخدام نفس الشروط السابقة، نريد فلترة الDocumentات التي تقييمها **ليس** أكبر من أو يساوي `9`، **وفي نفس الوقت** فئتها **لا** تحتوي على `"mobile"`.

```javascript
db.products.find({
    $nor: [
        { ratings: { $gte: 9 } }, 
        { category: "mobile" }    
    ]
})
```
*   **تحليل النتيجة:** سيعيد هذا الاستعلام فقط الDocumentات التي يقل تقييمها عن `9` وتخلو فئتها من كلمة `"mobile"` معاً .

---

## **ثالثاً: معامل التطابق الشامل (and Operator$)**

### **المفهوم وآلية العمل**
*   **التعريف:** يُستخدم المعامل `and$` لفلترة الDocumentات التي تستوفي **كافة الشروط (All conditions)** المحددة معاً في نفس الوقت. 
*   **المثال:** نريد إيجاد المنتجات التي تقييمها أكبر من أو يساوي `8`، **و** سعرها (`price`) أصغر من أو يساوي `500` .

### **طرق كتابة الاستعلام (Syntax Methods)**

**1. الطريقة الصريحة (Explicit Way):**
استخدام المصفوفة كما في المعاملات السابقة:
```javascript
db.products.find({
    $and: [
        { ratings: { $gte: 8 } },
        { price: { $lte: 500 } }
    ]
})
```

**2. الطريقة المختصرة (Shorthand Way):**
يمكن كتابة الشروط مباشرة داخل كائن التصفية (**Filter Object**) بوضع فاصلة (`,`) بينها، وستفهم **MongoDB** ضمنياً أن العلاقة بينها هي `and$`.
```javascript
db.products.find({ 
    ratings: { $gte: 8 }, 
    price: { $lte: 500 } 
})
```

### **لماذا نحتاج المعامل `and$` صراحةً إذا كانت الطريقة المختصرة موجودة؟**
*   **المشكلة البرمجية (Key Overriding):** في لغة جافا سكريبت (**JavaScript**)، إذا قمت بإنشاء كائن (**Object**) واستخدمت نفس المفتاح (**Key / Field name**) مرتين، فإن القيمة الثانية ستكتب فوق القيمة الأولى وتلغيها (**Overrides the first condition**) .
*   **مثال على الخطأ:** إذا كتبت `{ category: "mobile", category: "laptop" }`، سيتجاهل النظام شرط الـ "mobile" وسيبحث فقط عن الـ "laptop" .
*   **الحل:** عندما تحتاج إلى تطبيق شروط متعددة على **نفس الحقل (Same field)**، **يجب** عليك استخدام المعامل `and$` الصريح لتجنب مشكلة الكتابة الفوقية.

---

## **رابعاً: دمج المعاملات المنطقية (Combining Logical Operators)**
تكمن القوة الحقيقية في **MongoDB** في قدرتك على دمج عدة معاملات منطقية داخل استعلام واحد لإنشاء شروط معقدة.

*   **السيناريو:** نريد البحث عن المنتجات التي سعرها أكبر من `50`، **و** (فئتها إما `"mobile"` **أو** `"laptop"`) .
*   **التحليل:** لدينا شرط رئيسي (السعر > 50) يجب أن يتحقق دائماً، ولدينا شرط ثانوي مركب من خيارين. لحل ذلك، نستخدم معامل `$and` كحاضنة رئيسية، وبداخله نستخدم معامل `or$` .

**الكود المعماري للدمج:**
```javascript
db.products.find({
    $and: [
        { price: { $gt: 50 } }, // الشرط الأول للإلزام
        { 
            $or: [ // الشرط الثاني التخييري
                { category: "mobile" },
                { category: "laptop" }
            ] 
        }
    ]
})
```
(النتيجة: سيرجع الاستعلام كافة المنتجات التي يزيد سعرها عن 50، بشرط أن تكون فئتها إما هاتفاً أو حاسوباً محمولاً) .

---

## **خامساً: معامل النفي العكسي (not Operator$)**

### **المفهوم وآلية العمل**
*   **التعريف:** يقوم المعامل `not$` بعكس تأثير نتيجة التعبير أو الشرط المكتوب (**Reverses the effect of the query expression**) .
*   **آلية المعالجة:** إذا كان الشرط يرجع الDocumentات المطابقة، فإن إحاطته بمعامل `not$` سيجعله يرجع الDocumentات غير المطابقة.

### **التطبيق العملي**
*   **الاستعلام الأصلي:** إيجاد المنتجات التي سعرها أكبر من أو يساوي `1000`.
    `( { price: { $gte: 1000 } } )`
*   **الاستعلام المعكوس باستخدام `not$`:** إيجاد المنتجات التي سعرها **ليس** أكبر من أو يساوي `1000` (أي المنتجات التي يقل سعرها عن 1000) .

```javascript
db.products.find({
    price: { $not: { $gte: 1000 } }
})
```
(ملاحظة: معامل `$not` يُستخدم في حالات نادرة ومحددة، ويمكن غالباً تحقيق نفس النتيجة باستخدام معاملات المقارنة العكسية مثل `lt$`)*.
