
## **مقدمة: ما هو الإسقاط (Projection) ولماذا نحتاجه؟**
بعد الانتهاء من دراسة كيفية تصفية الDocumentات (**Filtering Documents**)، والعمل مع المؤشرات (**Cursors**)، وتطبيق الفرز وترقيم الصفحات (**Sorting & Pagination**)، ننتقل إلى مرحلة تشكيل البيانات (**Shaping the Data**).

*   **التعريف البرمجي للإسقاط (Projection):** هو ==عملية تحديد واختيار حقول معينة (**Fields**) لتضمينها أو استبعادها== من الDocumentات المسترجعة في مجموعة النتائج (**Result Set**).
*   **الهدف المعماري:** في الواجهات الأمامية (**UI**)، غالباً ما لا نحتاج إلى كافة بيانات الDocument. على سبيل المثال، عند عرض قائمة المنتجات، قد نحتاج فقط لاسم المنتج، سعره، وصورته، ولا نهتم بعرض تفاصيله الدقيقة أو فئته. باستخدام الإسقاط، نقوم بتقليل حجم البيانات المنقولة عبر الشبكة مما يرفع من أداء التطبيق .
*   وفقاً لتوثيق **MongoDB** الرسمي، يوجد أربعة معاملات أساسية للإسقاط وهي: **`$`**، **`$elemMatch`**، **`$slice`**، و **`$meta`**. سيركز هذا المرجع على الثلاثة الأولى.

## **القسم الأول: أساسيات الإسقاط (Basic Projection)**

### **الصياغة البرمجية (Syntax)**
تستقبل دالة `find` معاملين رئيسيين:
1.  **كائن التصفية (Filter Object):** وهو المعامل الأول. (إذا تركناه فارغاً `{}`، سيقوم بجلب كافة الDocumentات).
2.  **كائن الإسقاط (Projection Object):** وهو المعامل الثاني، وفيه نحدد الحقول التي نريدها.

### **قواعد التضمين والاستبعاد (Inclusion & Exclusion Rules)**
*   **التضمين:** نكتب اسم الحقل ونُسند له القيمة `1` (أو `true`) لإخباره بأننا نريد هذا الحقل في المخرجات.
*   **الاستبعاد الضمني:** أي حقل لا تقوم بكتابته وتحديده في كائن الإسقاط، سيتم استبعاده تلقائياً ولن يظهر في النتائج .
*   **استثناء المعرف التلقائي (id` Exception_`):** الحقل الوحيد الذي يشذ عن هذه القاعدة هو حقل `id_`. سيتم تضمينه دائماً بشكل افتراضي. لاستبعاده، يجب عليك استبعاده **صراحةً (Explicitly)** بتعيين قيمته إلى `0` (أو `false`) .

**مثال برمجي:**
نريد جلب كافة المنتجات، وعرض حقول الاسم، السعر، والتقييمات فقط، مع استبعاد المعرف `id_`.
```javascript
db.products.find(
    {}, // المعامل الأول: بدون تصفية (جلب الكل)
    { name: 1, price: 1, ratings: 1, _id: 0 } // المعامل الثاني: الإسقاط
)
```

## **القسم الثاني: الإسقاط على الDocumentات المضمنة (Embedded Documents Projection)**

### **1. الDocumentات المضمنة العادية (Single Embedded Document)**
إذا كان الDocument يحتوي على Document يخزن Documentاً مضمناً (مثل حقل `details` الذي يحتوي على `model` و `color` و `releaseYear`)، يمكننا استخراج حقول فرعية محددة منه باستخدام ** (Dot Notation)** .

```javascript
db.products.find(
    {},
    { 
        name: 1, 
        price: 1, 
        "details.model": 1, 
        "details.color": 1, 
        _id: 0 
    }
)
```
(النتيجة: سيتم إرجاع حقل `details` ككائن، ولكنه سيحتوي فقط على `model` و `color`، وسيتم استبعاد `releaseYear` لأنه لم يُذكر).

### **2. الDocumentات المضمنة داخل مصفوفة (Embedded Documents inside Arrays)**
في مجموعة الموظفين `employees`، لدينا حقل `skills` وهو عبارة عن مصفوفة (**Array**) تحتوي على Documentات مضمنة (لكل مهارة اسم `name` ومستوى `level`). 
*   **المتطلب:** نريد استرجاع اسم الموظف، ومصفوفة مهاراته بحيث تحتوي فقط على "اسم المهارة" دون مستواها .
*   **الحل:** نستخدم تدوين النقطة للوصول إلى الحقل داخل المصفوفة.

```javascript
db.employees.find(
    {}, 
    { name: 1, "skills.name": 1 }
)
```
(النتيجة: ستحتوي مصفوفة `skills` على كائنات تضم خاصية `name` فقط، ولن يظهر حقل `level`).

## **القسم الثالث: معاملات الإسقاط (Projection Operators)**

عندما تحتوي الحقول على مصفوفات (**Arrays**)، توفر **MongoDB** معاملات متقدمة لتحديد **أي العناصر** تحديداً نريد عرضها من تلك المصفوفة.

### **1. المعامل الموضعي (`$` Operator)**
*   **الوظيفة:** يُستخدم هذا المعامل لاستخراج **عنصر واحد فقط (Single element)** من مصفوفة، وهو العنصر الذي طابق شرط التصفية في الاستعلام.
*   **المشكلة التي يحلها:** إذا استعلمنا عن منتجات تنتمي لفئة الحواسيب المحمولة ("laptop"). المصفوفة قد تحتوي على `["electronics", "laptop"]`. في النتائج، لا نريد عرض "electronics"، بل نريد أن تحتوي المصفوفة المسترجعة على "laptop" فقط.
*   **الصياغة البرمجية:** يجب وضع اسم الحقل مع المعامل بين علامتي تنصيص `"$.category"`.

```javascript
db.products.find(
    { category: "laptop" }, // شرط التصفية
    { name: 1, price: 1, "category.$": 1 } // الإسقاط باستخدام المعامل $
)
```
(النتيجة: سيتم تغيير مصفوفة `category` في النتائج لتضم عنصراً واحداً فقط وهو "laptop")* .

*   **سلوك المعامل (`$`) مع معامل (`all$`):** إذا استخدمت `all$` في التصفية للبحث عن قيمتين معاً (مثل `["laptop", "electronics"]`)، فإن معامل الإسقاط `$` سيقوم بإرجاع **آخر عنصر (Last element)** تم تمريره في مصفوفة التصفية (في هذه الحالة "electronics"). وإذا عكست الترتيب، سيختار العنصر الأخير وفقاً للترتيب الجديد .

### **2. معامل مطابقة العناصر للإسقاط (elemMatch` Projection Operator$`)**
(ملاحظة: درسنا هذا المعامل سابقاً في عمليات التصفية، ولكنه يعمل هنا كمعامل إسقاط)*.
*   **الوظيفة:** ==يتيح لك هذا المعامل تضمين حقل المصفوفة في النتائج **فقط (Only if)** إذا كان أحد عناصرها يطابق شرطاً محدداً، وسيعرض== فقط العنصر المطابق .
*   **ميزة معمارية:** يمكن أن يكون شرط التصفية الأساسي مختلفاً تماماً عن شرط الإسقاط.
*   **المثال العملي:** نريد جلب المنتجات التي تقييمها أكبر من أو يساوي 8. ولكننا لا نريد إظهار حقل الفئة `category` في النتائج **إلا إذا** كانت الفئة تحتوي على كلمة "laptop" (وعندها نعرض كلمة laptop فقط).

```javascript
db.products.find(
    { ratings: { $gte: 8 } }, // التصفية بناءً على التقييم
    { 
        name: 1, 
        price: 1, 
        category: { $elemMatch: { $eq: "laptop" } } // شرط الإسقاط المستقل
    }
)
```
(النتيجة: سيتم إرجاع المنتجات المفلترة. المنتجات التي تحتوي مصفوفتها على "laptop" سيظهر بها حقل `category` كـ `["laptop"]`. أما المنتجات التي لا تمتلك "laptop" في فئتها، سيتم إخفاء وحذف حقل `category` منها تماماً في النتيجة المسترجعة) .

### **3. معامل القطع أو الاقتطاع (`slice` Operator$)**
*   **الوظيفة:** يُستخدم لتحديد نطاق محدد أو عدد معين من العناصر لاستخراجها من مصفوفة واستبعاد الباقي (**==Limit the number of elements returned from an array==**).
*   **طرق الاستخدام (Syntax Options):**

    **الطريقة الأولى: تمرير رقم صحيح (Number)**
    يُستخدم لجلب أول (أو آخر) N عناصر من المصفوفة.
    *   **المثال:** عرض أول فئتين فقط من مصفوفة الفئات .
    ```javascript
    db.products.find(
        {},
        { name: 1, category: { $slice: 2 } } // جلب أول عنصرين فقط
    )
    ```

    **الطريقة الثانية: تمرير مصفوفة للتخطي والتحديد `[skip, limit]`**
    يُستخدم لتخطي عدد معين من العناصر (عبر تحديد الـ **Index** الذي سنبدأ منه)، ثم جلب عدد محدد من العناصر التي تليه .
    *   **المثال:** تخطي العنصر الأول (Index 0)، والبدء من العنصر الثاني (Index 1)، وجلب عنصر واحد فقط (أي استخراج العنصر الثاني فقط) .
    ```javascript
    db.products.find(
        {},
        { name: 1, category: { $slice: } } 
        // [1 (Start Index), 1 (Number of elements to extract)]
    )
    ```
    (النتيجة: سيتم استرجاع العنصر الثاني فقط من مصفوفة الفئات لكل منتج)*.

## **خاتمة القسم (Conclusion)**
بهذا الدرس، يتم اختتام القسم الخاص بعمليات القراءة (**Read Operations in Depth**). لقد تم تغطية كافة الأدوات التي تمكن مهندس قواعد البيانات من الاستعلام عن الDocumentات باستخدام معاملات المقارنة (**Comparison Operators**)، المعاملات المنطقية (**Logical Operators**)، معاملات العناصر وتقييمها (**Element & Evaluation Operators**)، وصولاً إلى هندسة شكل البيانات المسترجعة باستخدام معاملات الإسقاط (**Projection Operators**). في الأقسام القادمة، سيتم الانتقال لدراسة عمليات التحديث (**Update Operations**).
