
## **مقدمة: لماذا نحتاج إلى معامل الزيادة (Increment Operator)؟**

في التطبيقات البرمجية الحقيقية، تُعد عمليات زيادة أو نقصان القيم (مثل زيادة عمر المستخدم، أو تعديل سعر منتج، أو تقليل عدد المخزون) من المهام الشائعة جداً (**Common Task**).

- **المشكلة مع معامل التعيين (`set$`):** بالطبع، يمكنك ببساطة استخدام معامل التعيين `set$` لتحديث قيمة حقل إلى رقم محدد. ولكن، ماذا لو كنت **لا تعرف القيمة الحالية (Current Value)** للحقل الذي تريد تغييره؟ في هذه الحالة، استخدام `set$` سيكون معقداً لأنه يتطلب جلب القيمة أولاً ثم إضافة الزيادة عليها برمجياً.
- **الحل المعماري:** لتسهيل هذه العملية، توفر **MongoDB** معاملاً مخصصاً لهذه المهمة يُسمى معامل الزيادة (**`$inc` Operator**). يقوم هذا المعامل بزيادة أو إنقاص القيمة الحالية مباشرة داخل قاعدة البيانات دون الحاجة لمعرفة قيمتها المسبقة.

---

## **آلية عمل معامل (`inc$`) والقواعد الأساسية**

- **نطاق العمل:** يُستخدم معامل `inc$` حصرياً مع الحقول الرقمية (**Number Fields**). لا يمكن استخدامه مع النصوص أو المصفوفات.
- **عملية الزيادة (Increment):** إذا قمت بتمرير **رقم موجب (Positive Number)** للمعامل، فسيقوم بزيادة القيمة الحالية للحقل بمقدار هذا الرقم.
- **عملية النقصان (Decrement):** لا يوجد معامل منفصل للنقصان في **MongoDB**. بدلاً من ذلك، نستخدم نفس المعامل `$inc` ولكن نمرر له **رقماً سالباً (Negative Number)**، وسيقوم تلقائياً بإنقاص القيمة الحالية للحقل بمقدار هذا الرقم.

(ملاحظة: يمكن استخدام معامل `inc$` مع دالة التحديث الفردي `updateOne` وكذلك مع دالة التحديث الجماعي `updateMany`) .

---

## **التطبيق العملي: استخدام معامل (`inc$`)**

لشرح المعامل، سنستخدم مجموعة المنتجات `products` (من ملف `products.json`)، وسنستهدف Documentاً يبلغ سعره الحالي `$3.99`، ونسخ المُعرف الفريد الخاص به (`id_`).

### **السيناريو الأول: زيادة القيمة (Incrementing Value)**

- **الهدف:** نريد زيادة سعر المنتج (`price`) بمقدار `100`.
- **الصياغة البرمجية:** نمرر كائن التصفية (**Filter Criteria**) أولاً للبحث عن الDocument باستخدام الـ `id_`، ثم نمرر كائن التحديث باستخدام معامل `inc$`.

```javascript
db.products.updateOne(
    { _id: ObjectId("...") }, // المعامل الأول: تصفية الDocument
    {
        $inc: { price: 100 }  // المعامل الثاني: زيادة السعر بمقدار 100
    }
)
```

- **تحليل النتيجة:** بعد تنفيذ الأمر في الـ **Mongo Shell**، أرجع الخادم رسالة تفيد بتعديل Document واحد (`modifiedCount: 1`). عند الاستعلام عن الDocument، أصبح السعر الجديد `$4.99` (تمت إضافة 100 إلى السعر القديم 3.99) .

### **السيناريو الثاني: إنقاص القيمة (Decrementing Value)**

- **الهدف:** نريد إنقاص سعر نفس المنتج بمقدار `200`. (السعر الحالي هو 499).
- **الصياغة البرمجية:** نستخدم نفس الكود السابق، ولكن نعين قيمة سالبة `-200`.

```javascript
db.products.updateOne(
    { _id: ObjectId("...") },
    {
        $inc: { price: -200 } // إنقاص السعر بمقدار 200
    }
)
```

- **تحليل النتيجة:** تم تعديل الDocument بنجاح، وانخفض السعر من `$4.99` إلى `$2.99`.

## **دمج المعاملات (Combining Operators)**

من الميزات المعمارية القوية في **MongoDB** أنه يمكنك استخدام معاملات تحديث متعددة في نفس استعلام التحديث.

- **المتطلب:** لنفترض أننا نريد زيادة السعر (`price`) بمقدار `200`، **وفي نفس الوقت** نريد تحديث حقل التوفر (`available`) وتعيين قيمته إلى المنطقية `true` .
- **الحل:** يمكننا استخدام معامل الزيادة `inc$` جنباً إلى جنب مع معامل التعيين `$set` داخل نفس كائن التحديث.

```javascript
db.products.updateOne(
    { _id: ObjectId("...") },
    {
        $inc: { price: 200 },       // العملية الأولى: زيادة السعر
        $set: { available: true }   // العملية الثانية: تعيين التوفر
    }
)
```

- **النتيجة:** تم تنفيذ العمليتين بنجاح على نفس الDocument. أصبح السعر `$4.99`، وتغيرت حالة التوفر إلى `true`.

## **القيود المعمارية: خطأ التعارض (Conflict Error)**

- **القاعدة:** **لا يمكنك (You cannot)** استخدام معامل الزيادة `$inc` ومعامل التعيين `$set` على **نفس الحقل (Same Field)** وفي **نفس الوقت (At the same time)**.
- **مثال خاطئ:** أن تحاول زيادة السعر بمقدار `200` باستخدام `$inc`، ثم تحاول في نفس الاستعلام تعيين السعر إلى `500` باستخدام `$set` .

```javascript
// كود يطرح خطأ برمجي (Error)
db.products.updateOne(
    { _id: ObjectId("...") },
    {
        $inc: { price: 200 },
        $set: { price: 500 } // تعارض! استخدام $set على نفس الحقل price
    }
)
```

- **استجابة الخادم:** إذا قمت بتنفيذ هذا الكود، فسترفض **MongoDB** العملية وترمي خطأ صريحاً ينص على أن: "تحديث المسار price سيخلق تعارضاً" (**Updating the path price would create a conflict at price**).
- **التفسير:** لا يمكن لمحرك قاعدة البيانات تحديد أولوية التنفيذ على نفس الحقل في استعلام واحد، لذا فإنه يحمي البيانات بمنع هذا التعارض.
