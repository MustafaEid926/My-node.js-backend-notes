
## **مقدمة: عمليات التحديث في (MongoDB)**
بعد أن غطينا في الأقسام السابقة كيفية إدراج البيانات (**Insert Operations**) وقراءتها وتصفيتها (**Read Operations**)، ننتقل الآن إلى ركن أساسي آخر من أركان قواعد البيانات، وهو عمليات التحديث (**Update Operations**). 
*   **الهدف:** يركز هذا الدرس على استرجاع وتثبيت المفاهيم الأساسية لكيفية تعديل المستندات (**Documents**) الموجودة مسبقاً داخل مجموعة (**Collection**)، وفهم السلوك المعماري لمعامل التحديث الأساسي في **MongoDB**.

---

## **أولاً: دوال التحديث الرئيسية (Main Update Methods)**
لتحديث الDocumentات، توفر لنا **MongoDB** دالتين أساسيتين، يتم اختيار إحداهما بناءً على عدد الDocumentات المراد تعديلها:
1.  **دالة `updateOne`:** تُستخدم لتحديث **Document واحد فقط (Single Document)** يطابق شروط التصفية.
2.  **دالة `updateMany`:** تُستخدم لتحديث **Documentات متعددة (Multiple Documents)** دفعة واحدة بشرط أن تطابق جميعها معايير التصفية.

### **الهيكلة البرمجية (Syntax & Arguments)**
تستقبل كلتا الدالتين (`updateOne` و `updateMany`) معاملين رئيسيين (Two Arguments) كالتالي:
1.  **المعامل الأول (Filter Criteria):** كائن (**Object**) يمثل معيار التصفية. يُستخدم للبحث عن الDocument أو الDocumentات التي نريد تحديثها.
2.  **المعامل الثاني (Update Document):** كائن آخر نستخدم بداخله معاملات التحديث (**Update Operators**) لتحديد الحقول التي نريد تغييرها والقيم الجديدة التي نريد تعيينها.

---

## **ثانياً: فهم معامل التعيين (`$set` Operator)**
يُعد المعامل **`set$`** الأداة الرئيسية لتعديل قيم الحقول داخل الDocumentات. ولهذا المعامل سلوكان معماريان في غاية الأهمية يجب على كل مهندس بيانات إدراكهما:
*   **القاعدة الأولى (تحديث حقل موجود):** إذا كان الحقل المذكور في كائن الـ `set$` موجوداً بالفعل داخل الDocument، فسيتم **تحديث قيمته (Updated)** واستبدالها بالقيمة الجديدة المحددة .
*   **القاعدة الثانية (إضافة حقل جديد):** إذا كان الحقل المذكور **غير موجود (Does not exist)** أصلاً في الDocument، فلن يطرح النظام خطأ، بل س==يقوم **بإنشاء هذا الحقل (Created)**== وإضافته للDocument مع تعيين القيمة المحددة له.

## **ثالثاً: التطبيقات العملية (Practical Applications)**

### **التطبيق الأول: تحديث حقل مصفوفة في Document واحد**
لنفترض أننا استعلمنا عن مجموعة الموظفين `employees` (والتي تحتوي على 5 Documentات). نريد تحديث مصفوفة الهوايات (`hobbies`) لموظف محدد (اسمه John Smith) باستخدام دالة `updateOne`.

*   **العملية:** سنقوم بفلترة الموظف باستخدام المعرف الفريد الخاص به `id_`، ثم نستخدم `set$` لتغيير المصفوفة الحالية (التي تحتوي على sports, music, cooking) إلى مصفوفة جديدة تحتوي فقط على (`sports`, `reading`).

**الكود البرمجي:**
```javascript
db.employees.updateOne(
    { _id: ObjectId("...") }, // المعامل الأول: فلترة الDocument المطلوب
    { 
        $set: { 
            hobbies: ["sports", "reading"] // المعامل الثاني: القيم الجديدة
        } 
    }
)
```
*   **نتيجة التنفيذ:** سيعرض الخادم رسالة تفيد بأن `matchedCount: 1` (تم العثور على Document واحد يطابق الشرط)، و `modifiedCount: 1` (تم تعديل هذا الDocument بنجاح) .

---

### **القاعدة المعمارية: ماذا يحدث عند التحديث بنفس القيم؟**
ماذا لو قمنا بتنفيذ **نفس أمر التحديث السابق تماماً** مرة أخرى على نفس الDocument وبنفس القيم؟
*   **النتيجة:** سيعرض الخادم `matchedCount: 1`، ولكن المفاجأة أن `modifiedCount` ستكون **`0`**.
*   **التفسير البرمجي:** تمتلك **MongoDB** آلية تحسين ذكية (**Optimization**). عندما تكتشف القاعدة أن القيمة الجديدة التي تحاول تعيينها مطابقة تماماً للقيمة الحالية الموجودة في الDocument، فإنها **تتجاهل عملية التحديث (skips the update operation)** لتوفير الموارد وتحسين الأداء. ولن يتم احتساب التعديل إلا إذا كانت القيمة المدخلة مختلفة فعلياً.

---

### **التطبيق الثاني: إضافة حقل جديد لDocumentات متعددة (`updateMany`)**
في مجموعة الموظفين، يمتلك كل موظف مصفوفة لمهاراته `skills` (كل مهارة هي Document مضمن يحتوي على `name` و `level`).
*   **الهدف:** نريد البحث عن **كافة الموظفين** الذين يمتلكون مهارة المطور (`developer`)، وإضافة حقل جديد كلياً لبياناتهم يُسمى `isDeveloper` وتعيين قيمته إلى المنطقية `true` [5، 6].

**الكود البرمجي:**
```javascript
db.employees.updateMany(
    { "skills.name": "developer" }, // تصفية الموظفين المطورين فقط
    { 
        $set: { 
            isDeveloper: true // إنشاء حقل جديد لعدم تواجده مسبقاً
        } 
    }
)
```
*   **نتيجة التنفيذ:** تم العثور على 4 Documentات (`matchedCount: 4`) وتم تعديلهم جميعاً (`modifiedCount: 4`). 
*   بمراجعة البيانات، سنجد أن الموظفين الأربعة أُضيف لهم الحقل الجديد `isDeveloper: true`. أما الموظف الخامس (الذي كانت مهاراته tester و designer فقط) فلم يتم إضافة الحقل له لأنه لم يطابق معيار التصفية في الأساس .

---

### **التطبيق الثالث: تحديث حقول متعددة معاً لDocument واحد**
معامل `set$` لا يقتصر على تحديث حقل واحد، بل يمكن استخدامه لتحديث أو إضافة **عدة حقول (Multiple fields) في نفس الوقت** داخل Document واحد.

لنفترض أننا نتعامل مع مجموعة المنتجات `products`، ونريد تحديث منتج معين (باستخدام الـ `_id` الخاص به). نريد تنفيذ 3 تعديلات معاً:
1.  تغيير السعر (`price`) من 129 إلى 139.
2.  تغيير حالة التوفر (`available`) من `true` إلى `false`.
3.  إضافة حقل خصم جديد (`discount`) لم يكن موجوداً مسبقاً بقيمة 10.

**الكود البرمجي:**
```javascript
db.products.updateOne(
    { _id: ObjectId("...") },
    { 
        $set: { 
            price: 139,             // تحديث قيمة موجودة
            available: false,       // تحديث قيمة موجودة
            discount: 10            // إضافة حقل جديد
        } 
    }
)
```
*   **نتيجة التنفيذ:** بمجرد التنفيذ، يتم تطبيق كافة هذه التعديلات دفعة واحدة على الDocument المستهدف بنجاح (`matchedCount: 1`, `modifiedCount: 1`) .

**الخلاصة:**
يُعتبر معامل `set$` المعامل الجوهري في عمليات التحديث. سواء كنت تقوم بتعديل Document واحد أو مجموعة من الDocumentات، وسواء كنت تقوم بتغيير بيانات حالية أو حقن حقول جديدة كلياً في هيكل الDocument، فإن `set$` يتولى هذه المهمة بمرونة وذكاء معماري يمنع التحديثات المتكررة غير الضرورية.
