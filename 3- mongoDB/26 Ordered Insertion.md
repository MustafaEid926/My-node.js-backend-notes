
## **مقدمة: التعمق في عمليات الإدراج (Insert Operations in Depth)**
بعد التعرف على أساسيات عمليات (CRUD) وهندسة البيانات والمخططات، ننتقل إلى دراسة سلوكيات متقدمة لعمليات الإدراج في **MongoDB**. لقد تعلمنا سابقاً أننا نستخدم الدالة `insertOne` لإدراج Document واحد، والدالة `insertMany` لإدراج Documentات متعددة دفعة واحدة. 
يركز هذا الدرس بشكل أساسي على كيفية تعامل الخادم مع إدراج الدفعات الكبيرة (**Bulk Insertion**) عبر دالة `insertMany`، من خلال مفهومين أساسيين: الإدراج المنظم والإدراج غير المنظم .

---

## **أولاً: الإدراج المنظم (Ordered Insertion)**

### **المفهوم البرمجي والسلوك الافتراضي**
*   **التعريف:** الإدراج المنظم (**Ordered Insertion**) يعني أن كل Document تقوم بتمريره داخل المصفوفة للدالة `insertMany` سيتم معالجته بشكل مستقل ومتسلسل (واحداً تلو الآخر) بنفس الترتيب الذي كُتب به داخل المصفوفة .
*   **سلوك الخطأ (Error Behavior):** إذا فشلت عملية إدراج أحد الDocumentات (لأي سبب برمجي)، فإن **MongoDB** ستقوم فوراً بإلغاء وإنهاء عملية الإدراج بالكامل بدءاً من نقطة الفشل. هذا يعني أن أي Documentات تلي الDocument الخاطئ في المصفوفة **لن يتم إدراجها إطلاقاً** .
*   **قاعدة التراجع (No Rollback Rule):** على الرغم من إيقاف العملية، فإن **MongoDB** **لا تتراجع (Does not roll back)** عن الDocumentات التي نجحت في إدراجها قبل حدوث الخطأ. الDocumentات السابقة تظل محفوظة في المجموعة (**Collection**) .
*   **الملاحظة الذهبية:** السلوك الافتراضي (**Default Behavior**) لدالة `insertMany` هو الإدراج المنظم (**Ordered Insertion**).

---

## **التطبيق العملي: كيف يعمل (Ordered Insertion)؟**
لتوضيح الفكرة، سنقوم بإنشاء Collection جديدة تُسمى `countries` داخل قاعدة البيانات لحفظ بيانات الدول. 
*   **هيكلة البيانات:** سنستخدم كود الدولة كمعرف فريد `id_`، وحقل `name` لاسم الدولة.

### **1. إدراج الدفعة الأولى بنجاح (Successful Insertion)**
```javascript
db.countries.insertMany([
    { _id: "in", name: "India" },             // Index 0
    { _id: "FR", name: "France" },            // Index 1
    { _id: "UK", name: "United Kingdom" }     // Index 2
])
```
*   **النتيجة:** سيتم إدراج الDocumentات الثلاثة بنجاح والتسلسل يبدأ من الفهرس `0`. لن يحدث أي خطأ لأن قيم المعرف `id_` فريدة لكل Document .

### **2. محاولة إدراج دفعة ثانية تحتوي على خطأ (Triggering an Error)**
الآن، ماذا يحدث لو حاولنا إدراج دفعة جديدة ولكن أحدها يمتلك `id_` مكرراً (موجود مسبقاً في قاعدة البيانات)؟ نعلم أن **MongoDB** تمنع تماماً وجود Documentين بنفس قيمة الـ `id_` داخل نفس الCollection لتجنب تعارض المفتاح الأساسي (**Duplicate Key Error**) .

```javascript
// عملية إدراج منظم (السلوك الافتراضي)
db.countries.insertMany([
    { _id: "P", name: "Pakistan" },                 // الDocument الأول (صالح)
    { _id: "FR", name: "France" },                  // الDocument الثاني (خاطئ - مكرر)
    { _id: "USA", name: "United States of America"} // الDocument الثالث (صالح)
])
```
*   **تحليل ما سيحدث خلف الكواليس:**
    1.  سيقوم الخادم بمعالجة الDocument الأول (Pakistan) ويدرجه بنجاح.
    2.  سينتقل للDocument الثاني (France)، وسيكتشف أن المعرف `FR` موجود مسبقاً. سيقوم النظام بطرح خطأ برمجي (**Duplicate Key Error**) ويوقف العملية بأكملها فوراً .
    3.  بسبب توقف العملية، لن يتم النظر للDocument الثالث (USA) ولن يتم إدراجه، رغم أنه Document صالح برمجياً ولا توجد به مشكلة.
*   **استجابة الخادم:** سيُظهر الخادم رسالة خطأ للDocument في الفهرس `1`، ولكن سيُظهر أيضاً أن عدد الDocumentات المدرجة (`insertedCount`) هو `1` (وهو Document Pakistan).

## **ثانياً: الإدراج غير المنظم (Unordered Insertion)**
في العديد من السيناريوهات، نحن لا نريد إيقاف العملية بأكملها بسبب Document واحد خاطئ. بل نريد إدراج الDocumentات الصالحة، وتخطي الDocumentات التي تحتوي على مشاكل. هنا نلجأ إلى الإدراج غير المنظم (**Unordered Insertion**) .

### **المفهوم البرمجي والسلوك**
*   **التعريف:** في هذا الوضع، تقوم قاعدة البيانات بمعالجة الDocumentات بشكل غير مرتبط. إذا واجهت Document به خطأ، فإنها ترفض إدراجه وتطرح رسالة خطأ، ولكنها **تستمر (Continues)** في عملية معالجة وإدراج بقية الDocumentات الصالحة الموجودة في المصفوفة .

### **كيفية تجاوز السلوك الافتراضي (Overriding Default Behavior)**
لتحويل عمل الدالة `insertMany` إلى إدراج غير منظم، يجب تمرير معامل ثانٍ (**Second Argument**) للدالة.
*   المعامل الأول هو مصفوفة الDocumentات.
*   المعامل الثاني هو كائن خيارات (**Options Object**) نقوم بداخله بتعيين الخاصية **`ordered`** إلى القيمة المنطقية **`false`**.

### **التطبيق العملي على (Unordered Insertion)**
لنقم بتنفيذ نفس الكود السابق ولكن مع تغيير بسيط: تفعيل الإدراج غير المنظم، وتغيير الدولة الأولى لتجنب الخطأ المكرر.

```javascript
db.countries.insertMany([
    { _id: "BD", name: "Bangladesh" },              // الDocument الأول (صالح)
    { _id: "FR", name: "France" },                  // الDocument الثاني (خاطئ - مكرر)
    { _id: "USA", name: "United States of America"} // الDocument الثالث (صالح)
], 
{ ordered: false } // المعامل الثاني لتعطيل الإدراج المنظم
)
```
*   **تحليل المخرجات:** 
    *   سيطرح الخادم رسالة خطأ لتوضيح فشل إدراج الDocument الثاني (بسبب تكرار المفتاح `FR`) .
    *   ولكن، بما أننا نستخدم الإدراج غير المنظم، فإن الخادم لن يتوقف؛ سيعالج الDocument الثالث (USA) ويدرجه بنجاح .
    *   قيمة الـ (`insertedCount`) ستكون `2` (للدولتين Bangladesh و USA).

## **ملخص القواعد المعمارية الهامة (Architectural Rules)**
1.  **قاعدة التراجع (Rollback Rule):** سواء كنت تستخدم الإدراج المنظم أو غير المنظم، فإن **MongoDB** **لا تقوم أبداً بالتراجع (Never roll back)** أو مسح الDocumentات التي نجحت بالفعل في إدراجها في قاعدة البيانات قبل حدوث الخطأ .
2.  **حصرية التطبيق (Scope of Application):** مفهومي الإدراج المنظم وغير المنظم يطبقان حصرياً فقط على دالة **`insertMany`**. ولا وجود لهذين المفهومين مع دالة `insertOne`، لأنها مصممة من الأساس لإدراج Document واحد فقط ولا تمتلك مصفوفة متسلسلة ليتم تنظيمها. 
3.  **المعرف الفريد (Unique `_id`):** يستخدم حقل `id_` بشكل أساسي في **MongoDB** لتعريف كل Document بشكل فريد داخلياً. ولا يُسمح مطلقاً بوجود Documentين يمتلكان نفس الـ `id_` داخل نفس الـ **Collection**.
