
## **مقدمة: التعامل مع حقول المصفوفات (Array Fields)**
بعد دراسة كيفية تحديث العناصر الموجودة داخل المصفوفات، ننتقل في هذا الدرس إلى تعلم الطرق المختلفة لإضافة عناصر جديدة (**Adding new elements**) إلى حقل مصفوفة داخل المستند (**Document**). 
*   **بيئة العمل:** سيتم تطبيق العمليات على مجموعة الموظفين **`employees collection`**، وتحديداً استهداف الموظف "John Smith" الذي يمتلك مصفوفة مهارات (**`skills array`**) تحتوي حالياً على مهارتين فقط: `developer` و `tester` .

---

## **أولاً: إضافة عناصر باستخدام معامل (`push Operator$`)**

### **1. إضافة عنصر مفرد (Pushing a Single Element)**
*   **الهدف:** إضافة مهارة جديدة كلياً (مثل: مطور شامل `full stack` بمستوى `4`) إلى مصفوفة مهارات الموظف "John Smith" .
*   **الوظيفة:** يُستخدم معامل **`push$`** لإلحاق وإضافة عنصر جديد إلى نهاية المصفوفة. يمكن أن يكون هذا العنصر قيمة بسيطة أو مستنداً مضمناً (**Embedded Document**).

**الكود البرمجي:**
```javascript
db.employees.updateOne(
    { name: "John Smith" }, // المعامل الأول: فلترة الDocument المطلوب
    { 
        $push: { 
            skills: { name: "full stack", level: 4 } // المعامل الثاني: إضافة العنصر للمصفوفة
        } 
    }
)
```
*   **تحليل النتيجة المعمارية:** بعد التنفيذ، سيرجع الخادم النتيجة `matchedCount: 1` و `modifiedCount: 1`. وعند الاستعلام عن الDocument، سنجد أن مصفوفة `skills` أصبحت تحتوي على 3 مهارات بعد إضافة المهارة الجديدة بنجاح.

### **2. السلوك المعماري لـ (`push$`) مع البيانات المكررة (Duplicate Data)**
*   **القاعدة الأساسية:** يسمح معامل **`push$`** بإضافة بيانات مكررة (**Duplicate records**) إلى المصفوفة دون أي قيود.
*   **مثال عملي:** إذا قمنا بتشغيل نفس الكود السابق تماماً مرة أخرى، فسيقوم الخادم بإرجاع `modifiedCount: 1`، وسيضيف نفس الDocument المضمن `{ name: "full stack", level: 4 }` كعنصر رابع في المصفوفة. وبالتالي ستصبح المصفوفة تحتوي على سجلات مكررة.

---

## **ثانياً: إضافة عناصر متعددة وتنسيقها (Pushing Multiple Documents)**

لا يقتصر عمل `push$` على إضافة عنصر واحد؛ بل يمكن استخدامه لإضافة **عدة Documentات في نفس الوقت (Multiple documents at a time)** من خلال دمجه مع معاملات مساعدة.

### **1. استخدام معامل التوزيع (`each Operator$`)**
لإضافة أكثر من عنصر، لا يمكنك تمرير مصفوفة لـ `push$` مباشرة. بدلاً من ذلك، يجب استخدام معامل **`each$`** .
*   **الصياغة البرمجية:** نقوم بإسناد كائن (**Object**) إلى حقل المصفوفة `skills`، وداخل هذا الكائن نستخدم `each$` ونُسند إليه مصفوفة تحتوي على كافة العناصر الجديدة المراد إضافتها .

### **2. خيارات التنسيق المتقدمة (Modifiers: `$sort` & `$slice`)**
توفر **MongoDB** إمكانية تنسيق العناصر **قبل** إضافتها فعلياً إلى المصفوفة، وذلك باستخدام معاملات إضافية مع `$each`:

*   **معامل الفرز (`sort$`):** 
    يُستخدم لترتيب العناصر التي تحاول إضافتها (أو ترتيب المصفوفة ككل). 
    *   **مثال:** إذا كنا نضيف مهارتين جديدتين (`backend` بمستوى 4، و `full stack` بمستوى 2)، يمكننا تمرير `{ level: 1 }` لمعامل `sort$` لترتيب هذه المهارات تصاعدياً (**Ascending order**) بناءً على المستوى قبل إدراجها .
*   **معامل الاقتطاع (`slice$`):** 
    يُستخدم لاستخراج أو تحديد عدد معين من العناصر لإدراجها. 
    *   **مثال:** إذا حددنا `slice: 1`، سيتم أخذ **العنصر الأول فقط** من المصفوفة الممررة في `$each` وإضافته، وتجاهل الباقي. (ملاحظة: قام المحاضر بإزالة هذا الخيار من الكود النهائي لأنه أراد إدراج كافة العناصر).

**الكود البرمجي الشامل (إضافة متعددة مع فرز):**
```javascript
db.employees.updateOne(
    { name: "John Smith" },
    { 
        $push: { 
            skills: { 
                $each: [ // مصفوفة العناصر المراد إضافتها
                    { name: "backend", level: 4 },
                    { name: "full stack", level: 2 }
                ],
                $sort: { level: 1 } // فرز العناصر تصاعدياً قبل الإضافة
            } 
        } 
    }
)
```
*   **تحليل النتيجة:** تم تعديل الDocument، وأصبحت المصفوفة تحتوي على 6 مهارات. وبفضل معامل `sort$`، تم ترتيب العناصر المُضافة حديثاً بناءً على حقل `level` تصاعدياً .

## **ثالثاً: استخدام معامل الإضافة الفريدة (`addToSet Operator$`)**

في العديد من التطبيقات، قد **لا ترغب** بوجود بيانات مكررة داخل المصفوفة. في هذه الحالة، يجب التخلي عن `push$` واستخدام معامل **`addToSet$`**.

### **1. المفهوم وآلية العمل**
*   **التعريف البرمجي:** يضيف هذا المعامل العنصر إلى المصفوفة **فقط** إذا لم يكن موجوداً مسبقاً، مما يمنع التكرار (**Does not allow duplicate elements**).

### **2. القيود المعمارية لمعامل (`addToSet$`) مقارنة بـ (`push$`)**
هناك قاعدة برمجية صارمة ومهمة جداً عند استخدام `addToSet$`:
1.  **لا يمكن استخدامه لإضافة Documentات متعددة دفعة واحدة** (**Cannot add multiple documents**). يسمح بإدراج عنصر مفرد فقط في كل عملية .
2.  **لا يدعم خيارات التنسيق:** لا يمكنك استخدام دوال مثل `sort$` لفرز العناصر أثناء استخدام هذا المعامل.

### **3. التطبيق العملي وسيناريوهات الاستخدام**

**السيناريو الأول: محاولة إدراج قيمة مكررة (Duplicate Record)**
*   **الهدف:** محاولة إضافة مهارة `{ name: "full stack", level: 2 }` للموظف "John Smith". (هذه المهارة موجودة بالفعل في المصفوفة من الاستعلامات السابقة).
*   **الكود البرمجي:**
```javascript
db.employees.updateOne(
    { name: "John Smith" },
    { 
        $addToSet: { 
            skills: { name: "full stack", level: 2 } 
        } 
    }
)
```
*   **النتيجة المعمارية:** سيرجع الخادم `matchedCount: 1` ولكنه سيرجع `modifiedCount: 0`. تعرفت **MongoDB** على أن القيمة مكررة، لذا **منعت التحديث (Did not update)** ولم يتم إدراج العنصر.

**السيناريو الثاني: إدراج قيمة فريدة (Unique Record)**
*   **الهدف:** تعديل الكود السابق لتصبح القيمة `{ name: "full stack", level: 7 }`.
*   **النتيجة المعمارية:** بما أنه لا توجد مهارة في المصفوفة تمتلك مستوى `7` لاسم "full stack"، فإن هذه البيانات تُعتبر فريدة ولن تخلق تكراراً. بالتالي، أرجع الخادم `modifiedCount: 1` وتم إدراج العنصر في المصفوفة بنجاح .

---

## **الخلاصة (Summary)**
*   استخدم **`push$`** عندما ترغب في إضافة عنصر مفرد أو عناصر متعددة (باستخدام `each$`)، وعندما تحتاج إلى خيارات الفرز (`sort$`)، ولا تمانع وجود بيانات مكررة في المصفوفة.
*   استخدم **`$addToSet`** عندما يكون الحفاظ على تفرد البيانات (**Uniqueness**) داخل المصفوفة هو الأولوية، مع الأخذ في الاعتبار أنك ستضيف عنصراً واحداً فقط في كل عملية استعلام.
