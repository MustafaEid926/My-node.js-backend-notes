
## **مقدمة: ما هو الفهرس الفريد (Unique Index)؟**

في هذا الدرس، ننتقل إلى نوع جديد ومهم جداً من الفهارس يُسمى **الIndex الفريد (Unique Index)**.

- **التعريف البرمجي:** هو نوع من الفهارس يضمن أن الحقل (**Field**) الذي تم تطبيق الIndex عليه سيخزن **قِيماً فريدة فقط (Unique values)**.
- **القاعدة الأساسية:** عند تطبيق هذا الIndex على حقل معين، لا يمكن لأي مستندين (**Two Documents**) داخل نفس المجموعة (**Collection**) أن يمتلكا نفس القيمة لهذا الحقل.

### **الفهرس الافتراضي كأول مثال (The Default Index)**

كما تعلمنا سابقاً، تقوم **MongoDB** بإنشاء Index افتراضي على حقل المعرف **`id_`**.

- هذا الIndex الافتراضي هو بطبيعته **Index فريد (Unique Index)**، وهذا هو السبب المعماري الذي يمنع وجود Documentين في نفس المجموعة يحملان نفس قيمة الـ `id_`.

---

## **القسم الأول: استكشاف الفهارس الحالية (Exploring Existing Indexes)**

قبل إنشاء Index جديد، قام المحاضر باستكشاف الفهارس الموجودة حالياً على مجموعة المستخدمين (**Users Collection**).

### **استخدام دالة `getIndexes`**

لمعرفة الفهارس المُطبقة على مجموعة معينة، نستخدم دالة **`getIndexes()`**.

```javascript
db.users.getIndexes()
```

- **نتيجة الاستعلام في المحاضرة:** أظهرت هذه الدالة وجود Indexين:
    1. الIndex الأول: الIndex الافتراضي على حقل `id_`.
    2. الIndex الثاني: الIndex المركب (**Compound Index**) الذي تم إنشاؤه يدوياً في الدرس السابق على حقلي العمر (`age`) والجنس (`gender`).

---

## **القسم الثاني: متطلبات وكيفية إنشاء Index فريد (Creating a Unique Index)**

### **المتطلب البرمجي (The Requirement)**

باستخدام دالة **`()findOne`**، سنستعرض أول Document لمعرفة هيكل البيانات، ولاحظ وجود حقل للبريد الإلكتروني (**`email`**) لكل مستخدم.

- **الهدف:** نريد إنشاء Index فريد على حقل `email` لضمان عدم وجود مستخدمين اثنين يمتلكان نفس البريد الإلكتروني في النظام.

### **الصياغة البرمجية (Syntax)**

لإنشاء هذا الIndex، نستخدم دالة **`()createIndex`** ونُمرر لها معاملين (Two Arguments) كالتالي:

1. **المعامل الأول (تحديد الحقل):** نمرر كائناً نحدد فيه الحقل المراد فهراسته ونوع الترتيب. في حالتنا `{ email: 1 }` لترتيبه تصاعدياً (**Ascending order**).
2. **المعامل الثاني (خيارات التكوين - Configuration Options):** نمرر كائناً ثانياً يحتوي على إعدادات الIndex. لجعل الIndex فريداً، نستخدم الخاصية **`unique`** ونُسند إليها القيمة المنطقية (**Boolean Value**) **`true`**.

**الكود البرمجي للتنفيذ:**

```javascript
db.users.createIndex(
    { email: 1 },       // المعامل الأول: الحقل المستهدف والترتيب
    { unique: true }    // المعامل الثاني: جعل الIndex فريداً
)
```

```javascript
db.users.createIndex(
  { email: 1 },
  { unique: true, partialFilterExpression: { email: { $exists: true } } }
)

```

(النتيجة: تم إنشاء الIndex الفريد بنجاح على حقل البريد الإلكتروني).

## **القسم الثالث: التطبيق العملي واختبار الIndex (Testing the Unique Index)**

لإثبات أن الIndex يعمل بشكل صحيح ويمنع التكرار، سنقوم بإجراء اختبار حقن بيانات كالتالي:

### **1. تجهيز البيانات المكررة**

- قام المحاضر بنسخ قيمة البريد الإلكتروني (**`email`**) الموجودة في الDocument الأول من المجموعة.
- ثم قام بتجهيز Document جديد لإدراجه، مع تغيير كافة الحقول الأخرى (مثل تغيير العمر `age` إلى 62، والاسم `name` إلى "Alice Williams 1"، والجنس `gender` إلى أنثى، والمدينة `city` إلى دلهي "Delhi")، **ولكنه أبقى على نفس البريد الإلكتروني المنسوخ**.

### **2. محاولة الإدراج (Insertion Attempt)**

باستخدام دالة الإدراج الفردي **`()insertOne`**، سنحاول إدخال هذا الDocument الجديد:

```javascript
db.users.insertOne({
    name: "Alice Williams 1",
    age: 62,
    gender: "female",
    city: "Delhi",
    email: "البريد_الإلكتروني_المنسوخ_والمكرر@example.com" // نفس إيميل الDocument الأول
})
```

### **3. النتيجة المعمارية (Architectural Result)**

- عند تنفيذ الأمر، رفضت قاعدة البيانات الإدراج وأرجعت خطأً برمجياً صريحاً يُسمى: **(duplicate key error)** أي "خطأ المفتاح المكرر".
- **التفسير الهندسي:** حدث هذا الخطأ تحديداً على حقل `email`. لأننا نحاول إدراج قيمة بريد إلكتروني **موجودة بالفعل (Already exist)** في Document آخر داخل المجموعة.
- بما أننا أنشأنا Indexاً فريداً (**Unique Index**) على هذا الحقل مسبقاً، فإن محرك **MongoDB** لن يسمح بأي قيم مكررة وسيقوم بحماية Data Integrity من خلال إيقاف العملية وطرح الخطأ.

## **الخلاصة (Conclusion)**

يُعد **الIndex الفريد (Unique Index)** من أهم الأدوات التي يعتمد عليها مهندسو قواعد البيانات لفرض قيود فريدة (**Unique Constraints**) على البيانات (مثل أرقام الهواتف، الحسابات البنكية، أو البريد الإلكتروني). من خلال تمرير `{ unique: true }` كمعامل ثانٍ لدالة `createIndex()`، تضمن قاعدة البيانات استحالة وجود Documentين يمتلكان نفس القيمة في هذا الحقل المحدد.
